## 一、为什么需要成本优化与 ROI 分析

绝大多数团队在 VPS 上的支出里，**30%~45% 是"沉默浪费"**：闲置实例、过量配置、未压缩的存储、跨区流量、忘记关的测试机。成本优化的目标不是"盲目省钱"，而是把每一元支出映射到可衡量的业务价值。

ROI（投资回报率）视角能回答三个核心问题：

1. **该不该扩容？** —— 新增实例带来的边际收益是否大于边际成本？
2. **该不该买长期套餐？** —— 3 年付的折扣是否真能覆盖灵活性损失？
3. **该不该上云 / 换云？** —— 迁移成本 + 学习成本是否小于长期节省？

本手册提供一套可落地的框架：先建立成本模型 → 用 ROI 判断是否值得 → 用优化策略执行 → 用监控与 FinOps 持续治理。

## 二、成本模型：先搞清楚钱花在哪

### 2.1 定价模型分析

VPS 服务商主流定价模型可分为四类：

| 模型 | 计费粒度 | 灵活性 | 单价 | 适用场景 |
|------|----------|--------|------|----------|
| 按需（On-Demand / 小时付） | 按秒/小时 | 最高 | 最高 | 短期测试、流量突发、未知负载 |
| 预留（Reserved / 包年包月） | 预付 + 时长承诺 | 低 | 低 30%~70% | 长期稳定负载（≥70% 利用率） |
| 竞价（Spot / 竞价实例） | 按小时动态价 | 中（可被回收） | 低 60%~90% | 可中断批处理、CI、渲染 |
| 流量包 / 带宽峰值 | 按出流量计费 | 中 | 视地区 | 内容分发、API 网关 |

**关键认知**：单价最低 ≠ 总成本最低。预留实例需要"承诺利用率"撑住，竞价实例需要"容错架构"兜底，否则节省会变成故障。

### 2.2 TCO 总拥有成本计算

TCO（Total Cost of Ownership）= 直接成本 + 间接成本 + 隐性成本。只看月账单会系统性低估真实支出。

```
TCO(月) = 计算实例费
        + 块存储费
        + 对象存储/备份费
        + 出网带宽费
        + 负载均衡 / 公网 IP 费
        + 快照 / 镜像存储费
        + 监控 / 日志 / 告警费
        + 运维人力摊销（工时 × 时薪 / 月）
        + 故障停机机会成本（SLA 外损失）
        + 迁移 / 学习成本摊销
```

**示例**：一台"月付 ¥120"的 2C4G 实例，若加上 80GB SSD（¥20）、200GB 出流量（¥40）、公网 IP（¥10）、每天 15 分钟运维（¥150）、一次年度故障 4 小时停机损失（摊月 ¥80），真实 TCO ≈ ¥420/月，是账单价格的 **3.5 倍**。

### 2.3 隐藏成本识别

最容易踩坑的隐性成本：

- **出网带宽（Egress）**：入站通常免费，出站按量计费，跨国/跨区流量单价极高。
- **快照蔓延**：自动快照留存 30 天，30 份增量累积可能超过实例盘本身。
- **闲置公网 IP / 负载均衡**：不开机也持续计费。
- **日志与监控存储**：高频日志 + 长保留 = 隐性大头。
- **Nat 网关 / 私网流量**：部分云对私网跨区也计费。
- **汇率与税制**：美元定价 + 增值税 + 汇率波动。

> 经验法则：把"账单金额 × 1.8~2.5"作为 TCO 估算下限，逐项核对后再下结论。

### 2.4 按服务拆解成本

做成本治理前，先按服务维度拆分（用标签或账单导出）：

```
计算 45% | 存储 18% | 带宽 20% | 网络组件 7% | 监控日志 5% | 其他 5%
```

哪一栏超 30%，哪栏就是优化第一优先级。

## 三、ROI 分析：每一分钱是否值得

### 3.1 ROI 基础公式

```
ROI(%) = (收益 - 成本) / 成本 × 100%

优化项目 ROI 特化版：
净节省 = 优化后月成本 − 优化前月成本（取绝对值=节省额）
投入 = 改造工时 × 时薪 + 工具/迁移费 + 风险准备金
回收期(月) = 投入 / 月节省
```

**决策阈值**：回收期 < 3 个月 = 立即做；3~6 个月 = 排期做；> 6 个月 = 评估再做。

### 3.2 单用户成本（Cost Per User）

SaaS / 工具类服务必须算清：

```
单用户月成本 = 月度 TCO / 活跃用户数
单用户毛利 = 客单价 − 单用户月成本
```

当单用户成本 > 客单价的 40%，说明架构或定价出问题；当 < 10%，通常还有 Right-sizing 空间。

### 3.3 成本 vs 性能权衡

并非越便宜越好。用"单位成本性能"衡量：

```
性价比指数 = 关键指标(QPS/吞吐/渲染帧) / 月 TCO
```

提升配置若只带来 10% 性能但 50% 成本，性价比指数下降，不值得；
提升配置带来 80% 性能且 20% 成本，性价比指数上升，值得。

### 3.4 长期合约折扣的临界点

包年/包三年折扣常见 40%~70%，但要算"承诺利用率临界点"：

```
设按需月单价 P，预留折扣率 d，合约月数 M，迁移沉没成本 S
盈亏平衡利用率 U* = S / (P × d × M)
```

例：按需 ¥200/月，3 年付打 5 折（实付 ¥100/月），迁移沉没 ¥2000：
U* = 2000 / (100 × 36) ≈ 0.56 → 只要该实例利用率 > 56% 且能稳定跑满 3 年，买长合约才划算。
**低于此利用率，按需更优（保留灵活性）。**

## 四、优化策略：把钱省在刀刃上

### 4.1 预留实例 vs 按需实例

**决策矩阵：**

| 负载特征 | 推荐 | 理由 |
|----------|------|------|
| 7×24 稳定基载（利用率 >70%） | 预留/包年 | 锁定折扣，回收期最短 |
| 工作日 9~18 波动 | 按需 + 定时开关 | 避免为闲置时段买单 |
| 季节性峰值 | 基载预留 + 峰值按需 | 混合覆盖 |
| 实验/预发环境 | 按需 + 自动关停 | 灵活性优先 |

**混合策略（推荐）**：把 60%~70% 的稳定基载用预留锁定，剩余 30%~40% 用按需/竞价吸收波动。这比"全预留"省 15%~25%，比"全按需"省 40%~55%。

### 4.2 竞价 / Spot 实例策略

竞价实例可便宜 60%~90%，但会被回收。落地要点：

1. **无状态化**：任务从对象存储/队列取数据，结果写回，实例随时可弃。
2. **检查点（Checkpoint）**：长任务每 N 分钟存进度，回收后从断点续跑。
3. **多规格回退**：准备 3+ 种实例类型，一种被回收自动换另一种。
4. **多可用区分散**：避免单区现货枯竭。
5. **出价策略**：设上限为按需价的 100%~120%，防止价格尖峰反噬。

**适用**：CI 构建、数据批处理、视频转码、模型训练、爬虫、压测。

### 4.3 存储分层

把数据按访问频率分层，单价差异可达 10 倍以上：

| 层 | 访问频率 | 相对单价 | 用途 |
|----|----------|----------|------|
| 热（SSD/高性能云盘） | 实时 | 1.0× | 数据库、活跃文件 |
| 温（标准对象存储） | 天~周 | 0.3× | 备份、日志归档近期 |
| 冷（低频/归档） | 月~年 | 0.05×~0.1× | 合规归档、旧快照 |
| 删除/生命周期 | — | 0× | 过期日志、临时文件 |

**落地**：用生命周期规则自动把 30 天前日志转冷、365 天前删除；快照只保留 7 天日常 + 1 份月度。

### 4.4 带宽优化

出网流量常是隐形的"成本黑洞"：

- **CDN 前置**：静态资源走 CDN，回源流量大幅减少（通常省 60%~80% 出流量）。
- **压缩**：开启 Brotli/gzip，文本类体积降 60%~70%。
- **协议优化**：HTTP/2、TLS 会话复用、连接复用。
- **就近部署**：用户集中区放同区域实例，减少跨区/跨国流量。
- **流量包/95 计费**：大流量选 95 峰值或包月带宽，比按量更稳。

### 4.5 资源 Right-sizing

过量配置是最大浪费源。方法：

1. **采集基线**：连续 2~4 周采集 CPU/内存/磁盘 IO/网络 P95。
2. **找浪费**：CPU 均值 <20% 且峰值 <50% → 可降配；内存常驻 <40% → 可降配。
3. **阶梯验证**：先降一档跑 1 周，监控错误率/延迟无恶化再固化。
4. **自动 Right-sizing**：用监控告警 + 脚本周期性复核。

典型收益：降配 1~2 档可省 30%~50% 计算费，且多数业务无感知。

### 4.6 自动扩缩容（Auto-scaling）

用弹性换成本：

- **定时扩缩**：按业务日历（如电商大促前 1 小时扩容）。
- **指标驱动**：CPU >65% 扩容、<25% 缩容，设最小/最大实例数兜底。
- **预测式扩缩**：基于历史规律提前扩容，避免冷启动延迟。
- **缩容保护**：设冷却时间，防止抖动导致频繁伸缩。

**注意**：自动扩缩必须配合健康检查与优雅下线，否则省了钱却丢了请求。

### 4.7 成本分配标签

没有标签 = 无法归因。强制标签策略：

```
必填标签：
  owner        （责任人）
  env          （prod/staging/dev）
  team         （业务团队）
  cost-center  （成本中心）
  project      （项目）
  optimized    （是否已做 right-sizing：true/false）
```

用标签做 Showback：每个团队看到自己的真實 TCO；做 Chargeback：成本回流到对应预算。

### 4.8 多云成本对比

不要被单云锁定。对比维度：

- **同规格单价**（2C4G / 4C8G 标准化对比）
- **出网流量单价**（常被忽略）
- **同区域延迟**（影响用户体验，间接影响留存）
- **折扣政策**（长期合约、新用户、老用户续费）
- **隐性费用**（快照、IP、负载均衡、支持费）

**策略**：核心稳定负载放性价比最高的云，弹性/测试负载放有竞价资源的云，避免单点也避免过度分散（分散本身有运维成本）。

## 五、FinOps 实践

FinOps = 工程 + 财务 + 业务的协作文化，目标是"在正确的时间用正确的成本交付价值"。

### 5.1 预算告警

设置三级告警，避免月底"账单惊吓"：

```
绿区：实际 < 预算 80%  → 正常
黄区：80%~100%       → 周报提醒负责人
红区：> 100%          → 立即告警 + 自动限流/暂停非关键实例
```

### 5.2 Showback / Chargeback

- **Showback（展示）**：把成本按标签展示给各团队，不真正扣款，培养成本意识。
- **Chargeback（分摊）**：把成本计入团队/项目预算，与绩效/资源申请挂钩。

> 新手从 Showback 起步，组织成熟后再上 Chargeback，否则容易引发甩锅。

### 5.3 成本异常检测

异常类型：

- **突增**：某实例出流量单日 ×10（可能被盗刷/死循环）。
- **静默增长**：快照存储每月 +15%（生命周期规则失效）。
- **结构性偏移**：prod 占比异常上升（环境串用）。

检测方法：对每日成本做移动平均 + 3σ 阈值；或用同比/环比偏离度 > 30% 触发。

### 5.4 成本优化检查清单

- [ ] 已导出最近 3 个月账单并按服务/标签拆分
- [ ] 已识别 Top 3 成本项并设定优化目标
- [ ] 稳定基载已评估预留实例（回收期 < 6 个月）
- [ ] 可中断负载已迁移到竞价实例
- [ ] 存储已配置生命周期分层
- [ ] 静态资源已接 CDN + 压缩
- [ ] 所有实例已打必填成本标签
- [ ] 已配置预算三级告警
- [ ] 已设置 Right-sizing 复核周期（季度）
- [ ] 非生产环境已配置定时关停
- [ ] 已建立月度成本评审机制

## 七、实用脚本（PowerShell）

> 所有脚本使用 PowerShell 原生语法，Windows / PowerShell 7 / WSL 通用。把 `your-token` 换成真实 Token，区域与规格按实际调整。

### 7.1 计算单实例月度 TCO（含隐性成本）

```powershell
# 计算单实例真实 TCO（示意，参数按实际账单填）
function Get-InstanceTCO {
    param(
        [double]$ComputeMonthly,   # 计算实例月费
        [double]$BlockStorage,     # 块存储月费
        [double]$EgressGB,         # 出网流量 GB
        [double]$EgressRate,       # 出网单价 /GB
        [double]$PublicIP,         # 公网 IP 月费
        [double]$OpsMinutesDay,    # 每日运维分钟
        [double]$HourlyRate,       # 运维时薪
        [double]$DowntimeHoursYr,  # 年停机小时
        [double]$DowntimeLossPerHr # 每小时停机损失
    )
    $opsMonthly   = $OpsMinutesDay * 30 * ($HourlyRate / 60)
    $dtMonthly    = ($DowntimeHoursYr * $DowntimeLossPerHr) / 12
    $egressCost   = $EgressGB * $EgressRate
    $tco = $ComputeMonthly + $BlockStorage + $egressCost + $PublicIP + $opsMonthly + $dtMonthly
    [PSCustomObject]@{
        Compute      = [math]::Round($ComputeMonthly, 2)
        Storage      = [math]::Round($BlockStorage, 2)
        Egress       = [math]::Round($egressCost, 2)
        PublicIP     = [math]::Round($PublicIP, 2)
        Ops          = [math]::Round($opsMonthly, 2)
        Downtime     = [math]::Round($dtMonthly, 2)
        TCO          = [math]::Round($tco, 2)
        BillMultiple = [math]::Round($tco / $ComputeMonthly, 2)
    }
}

# 示例：账单 ¥120 的实例，真实 TCO 演示
Get-InstanceTCO -ComputeMonthly 120 -BlockStorage 20 -EgressGB 200 -EgressRate 0.2 `
                -PublicIP 10 -OpsMinutesDay 15 -HourlyRate 60 -DowntimeHoursYr 4 -DowntimeLossPerHr 240
```

### 7.2 ROI / 回收期计算

```powershell
function Get-OptimizationROI {
    param(
        [double]$BeforeMonthly,  # 优化前月成本
        [double]$AfterMonthly,   # 优化后月成本
        [double]$Investment      # 改造投入（工时+工具+风险金）
    )
    $save = $BeforeMonthly - $AfterMonthly
    if ($save -le 0) { Write-Warning "该优化不省钱，ROI 为负"; return }
    $payback = $Investment / $save
    $annual  = $save * 12
    $roiPct  = ($annual - $Investment) / $Investment * 100
    [PSCustomObject]@{
        MonthlySave = [math]::Round($save, 2)
        AnnualSave  = [math]::Round($annual, 2)
        PaybackMonths = [math]::Round($payback, 1)
        ROI_1yr_Pct = [math]::Round($roiPct, 1)
        Verdict = if ($payback -le 3) {"立即做"} elseif ($payback -le 6) {"排期做"} else {"评估再做"}
    }
}

Get-OptimizationROI -BeforeMonthly 420 -AfterMonthly 260 -Investment 900
```

### 7.5 成本异常检测（3σ 移动平均，示意）

```powershell
function Find-CostAnomaly {
    param(
        [double[]]$DailyCost,   # 最近 N 天每日成本
        [double]$Sigma = 3      # 标准差倍数
    )
    $mean = ($DailyCost | Measure-Object -Average).Average
    $sd   = [math]::Sqrt(($DailyCost | ForEach-Object { [math]::Pow($_ - $mean, 2) } | Measure-Object -Average).Average)
    $threshold = $mean + $Sigma * $sd
    $last = $DailyCost[-1]
    [PSCustomObject]@{
        Mean        = [math]::Round($mean, 2)
        StdDev      = [math]::Round($sd, 2)
        Threshold   = [math]::Round($threshold, 2)
        Latest      = $last
        IsAnomaly   = $last -gt $threshold
        Suggestion  = if ($last -gt $threshold) { "触发异常，检查突增来源" } else { "正常" }
    }
}

Find-CostAnomaly -DailyCost @(120,118,125,121,119,130,480)
```

### 案例 A：跨境电商 —— 从全按需到混合架构

- **背景**：2C4G × 8 台全按需，月账单 ¥3,200，大促期间频繁卡顿。
- **动作**：稳定基载 5 台转包年（省 45%），3 台峰值留按需；静态资源接 CDN（出流量 −72%）；数据库盘从 SSD 降为高性能云盘（省 30%）。
- **结果**：月成本 ¥3,200 → ¥1,780（**−44%**），大促靠弹性扩容反而更稳。回收期 < 2 个月。

### 案例 B：AI 训练团队 —— 竞价实例 + 检查点

- **背景**：模型训练全用按需 GPU，月 ¥18,000，任务常因成本被砍。
- **动作**：训练任务无状态化 + 每 10 分钟检查点；多规格回退（3 种 GPU）；非高峰时段跑。
- **结果**：单位训练成本 −68%，月 ¥18,000 → ¥5,800，且因检查点机制零进度损失。

### 案例 C：SaaS 初创 —— 单用户成本失控

- **背景**：客单价 ¥29/月，但单用户 TCO 达 ¥14（48%），毛利被压缩。

- **结果**：单用户成本 ¥14 → ¥6.2（**21%**），毛利转正，融资讲故事更有底气。

## 十、FAQ

**Q1：预留实例买几年最划算？**
看利用率稳定性。利用率 >80% 且业务稳定 → 3 年；60%~80% → 1 年；波动大 → 不买，用按需+竞价。

**Q2：竞价实例被回收会丢数据吗？**
只要做到无状态化 + 检查点，就不会。状态严格外置到对象存储/数据库。

**Q3：Right-sizing 会不会影响性能？**
降配前看 P95 峰值而非均值。若峰值 <50%，降一档基本无感知；降后跑 1 周监控确认。

**Q4：小团队需要做 FinOps 吗？**
需要，但可以轻量：先 Showback（看自己的钱花哪），再上预算告警，最后才 Chargeback。

**Q5：CDN 一定省钱吗？**
动态内容多的业务，CDN 主要提升速度而非省钱；静态资源多的业务，CDN 通常省 60%+ 出流量。

**Q6：多云会不会更贵？**
过度分散会增加运维成本。建议"主力云 + 弹性云"双云，而不是 N 云各放一点。

**Q7：怎么说服老板做成本优化？**
用 ROI 说话：回收期 < 3 个月的项目，投入产出比一目了然，附本手册的 TCO 算法即可。

**Q8：隐藏成本里最容易被忽略的是哪个？**
出网带宽 + 快照蔓延。两者加起来常占 TCO 的 20%~35%。
